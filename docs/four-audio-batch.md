# تبدیل همزمان چهار فایل صوتی فارسی — ریلیز dars

این شاخهٔ مستقل، منطق موفق اجرای دو فایل قدیمی را بازاستفاده می‌کند و آن نتایج را تغییر نمی‌دهد.

## منبع تأییدشده

- Repository: `Shahbazi-Amir/vid_pipeline`
- Published release: https://github.com/Shahbazi-Amir/vid_pipeline/releases/tag/dars
- Tag: `dars`
- Run branch: `work/four-audio-persian-parallel`
- Workflow: `.github/workflows/four-audio-parallel.yml`

چهار فایل ویرایش‌ناپذیرِ مشخص‌شده با نام/شناسه/اندازه و SHA-256 در `scripts/transcribe_four_release.py` ثبت شده‌اند:
`1.m4a`, `2.m4a`, `3.m4a`, `4.m4a`.
PDF، PPTX و HTML هم‌ریلیز، اصلاً وارد صف صوت نمی‌شوند. قبل از اجرا، preflight اطلاعات چهار فایل را با داده‌های GitHub مطابقت می‌دهد؛ هنگام دانلود نیز اندازه و SHA-256 بررسی می‌شود. اگر Asset تغییر کند، اجرا به‌جای فایل اشتباه متوقف می‌شود.

## اجرا

فایل `ops/four-audio-batch/trigger.txt` فقط بعد از آماده‌شدن ورودی‌ها برای فعال‌کردن Actions تغییر داده می‌شود. `workflow_dispatch` نیز در صورت نیاز قابل استفاده است.

Workflow یک مرحلهٔ صحت‌سنجی و چهار اجرای مستقل (`max-parallel: 4`) دارد. هر Job از `python -m vid_pipeline.cli run-file` با مدل `large-v3-turbo`، زبان `fa`، CPU/int8، پروفایل `balanced`، صدای `safe` و `--no-editorial` استفاده می‌کند؛ مانند دو فایل قرآنی قبلی، ولی بدون prompt موضوعی قرآن چون محتوا هنوز معلوم نیست. چهار اجرا موازی *درخواستی* هستند؛ زمان‌بندی واقعی به سهمیه و ظرفیت GitHub Actions بستگی دارد.

پس از هر اجرا artifact مستقلی با ماندگاری ۳۰ روز تولید و نتیجه در همان شاخه ثبت می‌شود:
`outputs/four-audio-batch/01` تا `04`.
فایل‌های هر پوشه عبارت‌اند از:

- `transcript.md` و `transcript.txt` — متن اولیهٔ ماشینی
- `transcript.timestamped.md` و `transcript.raw.json` — متن زمان‌دار و قطعات اصلی
- `source.json`, `worker.log`, `status.json` — اطلاعات منبع، گزارش، وضعیت

اگر یکی از Jobها شکست بخورد، سه Job دیگر مستقل ادامه می‌دهند و خروجی‌های موجود ذخیره می‌شوند؛ مرحلهٔ جمع‌آوری تا موفقیت همهٔ چهار فایل سبز نخواهد بود.

## بازبینی نهایی

این مرحله خروجی اولیهٔ ماشینی است، **نه** متن شنیداری تأییدشده. متن کامل هر جلسه با خروجی زمان‌دار اینجا بازبینی می‌شود؛ برای موارد نامطمئن باید به صوت رجوع کرد. چهار فایل نهایی راست‌به‌چپ `01.md`, `02.md`, `03.md`, `04.md` مستقل از متن خام آماده می‌شوند. فایل‌های اولیه و لاگ‌ها حفظ خواهند شد.

**حریم خصوصی:** مخزن و ریلیز عمومی‌اند؛ این صوت‌ها برای همگان قابل دسترس هستند.
