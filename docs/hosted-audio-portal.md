# کارگاه آنلاین صوت و متن

شاخه: `feature/hosted-audio-portal`، منشعب از `work/quran-archive-transcription` در commit `bb900a73021ed88b497a98e715f77bc38d5456d1`.

## رفتار

رابط فارسی و راست‌چین Streamlit، صوت تا ۵۰۰ مگابایت می‌پذیرد. صوت با نام یکتای `portal-<id>.<ext>` به **همان ریلیز `rag_finance`** اضافه می‌شود؛ هیچ فایل قدیمی حذف یا جایگزین نمی‌شود. سپس یک درخواست تغییرناپذیر در `.portal/jobs/<id>.json` ثبت می‌شود. Push این درخواست روی همین شاخه، workflow `audio-portal.yml` را فعال می‌کند؛ نیازی به تغییر شاخهٔ اصلی نیست.

پردازش از همان فرمان استفاده‌شده برای دو جلسهٔ قبلی استفاده می‌کند: `python -m vid_pipeline.cli run-file`، مدل کنترل‌شدهٔ پروژه `large-v3-turbo`، CPU/int8، پروفایل balanced، صوت safe، و `--no-editorial`. متن اولیه، متن زمان‌دار، JSON بخش‌ها و مشخصات منبع در `outputs/audio-portal/<id>/` ماندگار می‌شوند. هش SHA-256 و اندازهٔ صوت پیش از اجرای موتور بررسی می‌شوند. بستن صفحه یا راه‌اندازی دوبارهٔ Streamlit، اجرای Actions را متوقف نمی‌کند.

پیشرفت در سطح مرحله نمایش داده می‌شود؛ درصد دقیق و زمان باقیمانده اندازه‌گیری نشده‌اند و نمایش داده نمی‌شوند. هر اجرای صف یک صوت دارد؛ چند درخواست می‌توانند همزمان اجرا شوند، مطابق سهمیهٔ حساب GitHub. محدودیت `max-parallel: 2` فقط داخل یک اجرای چندورودی است، نه سقف سراسری تمام اجراها. مهلت هر worker برابر ۳۵۰ دقیقه است. وضعیت timeout و cancellation از Actions نیز خوانده می‌شود.

## استقرار روی Streamlit Community Cloud

این مخزن شامل برنامهٔ آمادهٔ استقرار است؛ **وجود کد به معنی انتشار یک آدرس آنلاین نیست**. انتشار به حساب میزبان و ثبت اسرار نیاز دارد.

در فرم Create app:

- Repository: `Shahbazi-Amir/vid_pipeline`
- Branch: `feature/hosted-audio-portal`
- Main file path: `apps/audio_portal/app.py`
- Python: `3.11` یا نسخهٔ پشتیبانی‌شدهٔ سازگار
- Requirements کنار برنامه: `apps/audio_portal/requirements.txt`
- اسرار: مطابق `apps/audio_portal/secrets.example.toml`

`VID_PIPELINE_GITHUB_TOKEN` باید فقط به همین مخزن دسترسی داشته باشد؛ Contents: read/write و Actions: read لازم است. برای ثبت فایل‌های درخواست به شاخهٔ موجود، توکن شخصی محدود به مخزن یا GitHub App مناسب لازم است؛ توکن پیش‌فرض `GITHUB_TOKEN` برای صف ورودی مناسب نیست، چون push آن workflow دیگری را فعال نمی‌کند. توکن را در کد، ریلیز، چت یا فایل commit‌شده قرار ندهید. برنامه آن را از محیط یا `st.secrets` می‌خواند.

`PORTAL_ACCESS_PASSWORD` ورود به رابط را کنترل می‌کند؛ بدون آن برنامه بسته می‌ماند. این نسخه یک کارگاه مشترک با رمز مشترک است، نه سرویس چندمستأجری یا سامانهٔ عمومی ناشناس. همهٔ افراد دارای رمز، کارهای مشترک را می‌بینند. فایل و متن در مخزن و ریلیز مقصد قرار می‌گیرند؛ در مخزن عمومی، عمومی خواهند بود. پیش از ثبت، رابط تأیید این ذخیره‌سازی را می‌گیرد.

## میزبان Docker جایگزین

از ریشهٔ مخزن:

```bash
docker build -f apps/audio_portal/Dockerfile -t audio-portal .
docker run --env-file /secure/path/portal.env -p 8501:8501 audio-portal
```

برای آدرس عمومی، container را روی میزبان HTTPS سازگار مستقر کنید. Actions پردازش را انجام می‌دهد؛ میزبان Streamlit مدل ASR را بارگذاری نمی‌کند. تنظیم سقف reverse proxy میزبان باید با آپلود ۵۰۰MB سازگار باشد.

## بازبینی

فعلاً خروجی فقط **متن اولیهٔ ماشینی** است. تب بازبینی بستهٔ ZIP شامل متن کامل، نسخهٔ زمان‌دار، JSON خام، مشخصات منبع و دستور بازبینی می‌سازد. هیچ API مدل پولی یا بازنویسی خودکاری اجرا نمی‌شود.

مرحلهٔ بعد پیشنهادی: نمایش صوت و بندهای زمان‌دار کنار هم، ثبت تغییرات و توضیح اصلاح، ذخیرهٔ مستقل `transcript.reviewed.md`، و تأیید انسانی آیات/نام‌ها/ابهام‌ها. متن اصلی باید همیشه باقی بماند. تطبیق با صوت و منبع قرآن باید واقعی باشد؛ ویرایش زبانی را نباید با صحت‌سنجی صوتی یکی دانست.

## کنترل‌ها و محدودیت‌ها

- درخواست صف و خروجی اولیه تغییرناپذیرند؛ تلاش دوباره شناسهٔ تازه دارد و همان صوت را استفاده می‌کند.
- قطع پاسخ ثبت درخواست با خواندن نتیجه کنترل می‌شود تا درخواست تکراری نسازد.
- لینک دانلود موقت فایل، توکن گیت‌هاب را دریافت نمی‌کند.
- هیچ ادعای دقت صددرصد یا بازبینی کامل آیات در رابط وجود ندارد.
- این نسخه سهمیهٔ سراسری، احراز هویت فردی، حذف خودکار یا پاک‌سازی تاریخچهٔ مخزن ندارد. برای سرویس عمومی پرترافیک باید صف و مجوزها ارتقا یابند.
- در این نسخه فهرست همهٔ درخواست‌ها برای مرتب‌سازی خوانده می‌شود؛ برای حجم بالای کار باید صفحه‌بندی/ایندکس اضافه شود.
